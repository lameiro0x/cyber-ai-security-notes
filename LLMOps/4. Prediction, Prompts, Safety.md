# Parte teorica

## Deployment

![pasted_image_20260506110325.png](<../images/pasted_image_20260506110325.png>)

Maneras de hacer deployment:

- **Batch:** Hacerlo cada cierto tiempo y entrenar el modelo con esa informacion de ese tiempo de manera oofline y obtener predicciones

- **REST API** (esto lo hace la pipeline en la leccion anterior): Coger el modelo y deployeamos como una API, como un servicio. De manera online hago la prediccion en real time con la API.
	- Flask or FastAPI

### Load balancing

Basicamente esto se hace para. manejar el trafico y que no se pete un modelo

![pasted_image_20260506110929.png](<../images/pasted_image_20260506110929.png>)

### Mas alla del deployment

- Podemos **monitorizar** con metricas el modelo y comprobar su seguridad
- Tambien queremos cuidar la **escalabilidad**:
	- Cargar test
	- O tener un roll out controlado (que el trafico al principio no sea enorme y que vaya creciendo poco a poco y se vaya adaptando)
- Tambien se quiere una **buena latencia** entre respuestas, para solucionar la latencia alta:
	- Se pueden usar modelos mas pequenos
	- Procesadores mas rapido
	- O hacer el deployment solo por regiones cercanas al servidor con la API

#### Formato del prompt en produccion

Aqui es importante que queremos preguntar y tener el prompt de la misma forma que cuando se entreno 

![pasted_image_20260506113025.png](<../images/pasted_image_20260506113025.png>)


### Probablity vs Severity

Podrían sonar violentas si solo miramos las palabras **“pinned down”** o **“beat me”**. Un modelo de moderación o seguridad podría detectar lenguaje relacionado con agresión. Pero el contexto visual muestra **pandas pequeños**, lo que hace que la situación sea mucho menos grave y probablemente inofensiva o humorística.


>  **Probabilidad**: qué tan probable es que el contenido sea dañino.  
   **Severidad**: qué tan grave sería si realmente fuera dañino.

### Safety Attributes

Estos son partes del outputs que no queremos ver y automaticamente se bloquean y no se muestra en la respuesta final de "content"

Estos los podemos ver en el output anterior:

Que venia de estos comandos:
```python
### load the second object of the response
output = response._prediction_response[0][0]
```

```python
### print the second object of the response
pprint(output)
```

![pasted_image_20260506113514.png](<../images/pasted_image_20260506113514.png>)

Ahora en vez de usar "content"usaremos lo siguiente, para comprobar si algo de la pregunta fue blockeado:

```python
### retrieve the "blocked" key from the 
### "safetyAttributes" of the response
blocked = response._prediction_response[0][0]\
['safetyAttributes']['blocked']
```

```python
print(blocked)
```

![pasted_image_20260506113752.png](<../images/pasted_image_20260506113752.png>)

Como vemos da false, es decir no hay nada bloqueado

Tambien se manda un score y a partir de esto se puede bloquear una cosa o otros poniendo un limite a ese score de los safety attribute. podemos ver esos scores asi:

```python
### retrieve the "safetyAttributes" of the response
safety_attributes = response._prediction_response[0][0]\
['safetyAttributes']
```

```python
pprint(safety_attributes)
```

### Citas

Idealmente se quiere generar todo el contenido original como sea posible con el LLM

El `citationMetadata` se puede usar para comprobar y reducir las probabilidades de el LLM generar mucho contenido existente

Para comprobar los scores de esto y la inforamcion citada en la respuesta:

```python
### retrieve the "citations" key from the 
### "citationMetadata" of the response
citation = response._prediction_response[0][0]\
['citationMetadata']['citations']
```

```python
pprint(citation)
```

![pasted_image_20260506114422.png](<../images/pasted_image_20260506114422.png>)

La respuesta en este caso no tiene nada de citas
